# 独自ドメインへの切り替え手順

なぜ：会社のネットワークの多くは `github.io` をまとめて止めている（オーナーの会社でも、ほかの人の github.io のサイトも開けなかった。
2026-10-26）。自分のドメインで公開すれば、この一括ブロックに当たらない。あとでホスティングを GitHub Pages から別のサービスへ
移すときも、ドメインはそのまま使える。

## オーナーがやること

### 1. ドメインを買う
- ドメイン会社の例：お名前.com、Xserverドメイン、Cloudflare Registrar（.jp は扱っていない）など。
- 年額の目安：.com は千数百円から、.jp は三千円台から（更新料は会社とキャンペーンで変わる）。
- 候補：foldfeed.com／foldfeed.jp／foldfeed.org など。空いているかは各社のサイトで検索する。
- **WHOIS 情報公開代行**（住所・氏名・電話番号を公開しないオプション）を必ずオンに。**自動更新**もオンに。

### 2. GitHub でドメインの所有を確認する（乗っ取り防止。DNS をつなぐ前に）
1. GitHub の右上のアイコン → Settings → 左の「Pages」→「Add a domain」に買ったドメイン（例：`foldfeed.com`）を入れる。
2. 表示される TXT レコード（名前は `_github-pages-challenge-shakewakame` で始まる）を、ドメイン会社の DNS 設定に追加する。
3. GitHub の画面で「Verify」。反映まで数分〜数時間かかることがある。

### 3. ドメイン会社の DNS 設定
| 種類 | 名前（ホスト） | 値 |
|---|---|---|
| A | （空欄 または `@`） | `185.199.108.153` |
| A | （空欄 または `@`） | `185.199.109.153` |
| A | （空欄 または `@`） | `185.199.110.153` |
| A | （空欄 または `@`） | `185.199.111.153` |
| AAAA（任意） | （空欄 または `@`） | `2606:50c0:8000::153`、`2606:50c0:8001::153`、`2606:50c0:8002::153`、`2606:50c0:8003::153` |
| CNAME | `www` | `shakewakame.github.io` |

もとからある A レコード（ドメイン会社の駐車ページなど）が同じ名前にあれば消す。

### 4. リポジトリの Pages の設定
1. リポジトリ（shakewakame/Foldfeed）→ Settings → Pages →「Custom domain」にドメイン（例：`foldfeed.com`）を入れて Save。
2. DNS の確認が通るのを待つ（「DNS check successful」）。
3. 証明書ができたら「**Enforce HTTPS**」にチェック（数分〜1 日。チェックできないうちは待つ）。

設定が済むと、古い `https://shakewakame.github.io/Foldfeed/` は新しいドメインへ自動で転送される。

### 5. Claude にドメイン名を伝える

## Claude がやること（ドメインが決まったら）

- `config/editorial.json` の `site_url` を新しいアドレスに（毎日の号の PR に書くプレビューのリンクがここから作られる）。
- `docs/review-guide.md` の「確認待ちの一覧」のアドレス、`TODO.md` の公開先の記録を直す。
- PR の通知（`.github/workflows/notify.yml`）は GitHub Pages に設定されたアドレスを自動で使うので、直さなくてよい。
- サイトの中のリンクはすべて相対パスなので、サイト本体は直さなくてよい。

## 切り替えたあと

- 会社のネットワークで開けるか確かめる。取ったばかりのドメインは「新しく登録されたドメイン」「未分類」として止められることがある。
  そのときは、ブロック画面に出るフィルタ製品の分類申請の窓口に「科学・教育」として申請するか、情報システム部門に許可を頼む。
- ホーム画面に追加した「確認待ちの一覧」とブックマークは、新しいアドレスで作り直す（古いアドレスからも転送はされる）。
